# 记忆侧架构与模块收益

## 1. 检索与重排流水线（一次 `/search` 的实际路径）

```
query（可含图片）
   │
   ├─(① 查询图→文本桥)  若有图：VLM 生成"检索导向描述"→ "[Query image] …" 并入查询文本
   │                      向量模型仍只有 text-embedding-v4
   ▼
② 三路检索骨干  hybrid_round：稠密(text-embedding-v4) + 轮级稠密 + 稀疏(bm25_anchor)
   │              → 按"可观测轮结构"自动选融合制度（fusion=auto：多消息轮→RRF；否则→归一化分数）
   │              → round_emit=adjacent（同一轮两条消息都进池，供精排看到完整一轮）
   ▼
③ cross-encoder 精排  Qwen3-Reranker-4B（rerank_unit=round：以"整轮"为打分单位）
   ▼
④ LLM 证据选择档（仅 text 路）  gpt-4o-mini
   │   · 提示：列出所有含证据的候选（集合级多选）
   │   · 窗口按 request 去重（同一轮只出现一次）
   │   · 门控可开关：仅在 4B top1−top2 间距小时才调用（默认关闭）
   ▼
⑤ image 路（仅查询含图）  关系感知证据选择：结构化卡片 + 通用规则 + 逐对图像证据关系
   │                      硬闸：仅查询带图时启用；生效时替代 VL reranker
   ▼
⑥ 去重 / 水合（blob 缺失降级）/ 分数非递增契约 → 返回 data[]
```

## 2. 各模块的**局部**与**整体**收益（Mem-Gallery，全库 1,527 = image 487 + text 1,040）

| 模块 | 局部 Δ（R@1） | 整体 Δ（全库，leave-one-out 实测） |
|---|---|---|
| 查询图→文本桥 | 487 条：0.0720 → 0.2861（**+0.2141 ✅**） | **+0.0606 R@1 / +0.1624 Hit@1** |
| 关系感知证据选择 | 487 条：+0.0311 ✅ | +0.0075 R@1 / +0.0249 Hit@1 |
| LLM 证据选择档 | text 1,040：+0.0197 ✅（Hit@1 +0.0385 ✅） | +0.0100 R@1（换 gpt-4o-mini 前后两次全量对照） |
| 轮级打分单位 | text 1,040：+0.0170 ✅ | +0.0053 R@1（R@n_gold −0.0060） |
| 窗口按轮去重（修复） | text 1,040：R@n_gold +0.0166 ✅ | 未单独在全量隔离 |
| 4B cross-encoder | — | 阶梯累计 +0.0907 ✅（0.2899 → 0.3715） |

**读法**：局部回答"这个机制有没有用"，整体回答"它给最终系统买到多少"。
两者不是按比例缩放——模块修的是同一批错题、且 R@1 有 `1/|gold|` 天花板，故**不可相加**。

## 3. 关键设计取舍（都有实测依据）

1. **以"轮"为一级单位**（检索通道、精排单位、LLM 窗口都按轮）：失败最大类是同轮邻接轮顶替（占失败 ~50%）。
2. **LLM 只做"证据集合选择"，不做排序**：排序交给可控的 cross-encoder。
3. **图像不进向量层**：比赛限定 `text-embedding-v4`，故在查询阶段把图转文字。
4. **窗口按轮去重**：`round_emit=adjacent` + 轮级打分会让同一轮的两条**同分**，若不去重，
   喂给 LLM 的 12 个槽位里只有约 6 个不同轮，多选型提示会把预算浪费在重复副本上。
5. **门控默认关闭**：它只在"LLM 档本身会把已对的 top-1 改错"时（弱模型/激进提示）才有价值；
   换成温和的 `round_rank` 提示后其边际效应为 −0.0015（噪声内），故关闭。

## 4. 评测口径说明（重要）

本目录所有"整体"数字均为**单次端到端跑完全库**（`MemoryService.search`）的结果，
不是把不同实验的逐样本结果拼接而成；跨数据集的结论不互推（同一配置在 Mem-Gallery 与 ATM-Bench 上偏好不同）。
